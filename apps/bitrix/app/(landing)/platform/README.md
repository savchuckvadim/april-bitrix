# Раздел /platform — продающие страницы сервисов

Главная `/platform` и страницы сервисов `/platform/<slug>` для руководителей и собственников
партнёров ГАРАНТ. Отдельная группа маршрутов `(landing)` со своей шапкой и подвалом:
страницы сайта `(site)` (`/home`, `/offer`, `/renewal`) не меняются.

## Правило текстов

Каждый блок начинается с выгоды клиента, функция — доказательство. Обещать можно только то,
что есть в коде: перед правкой текста сверяйтесь с кодом сервиса. Что уже сверено и снято
(счёт-оферта, «сбытовые сигналы», рубли потерь по каждому менеджеру, «установка за 5 минут»),
записано в комментариях к файлам `model/services/*` и в тесте `__tests__/services.test.ts`.

## Где что лежит

| Что | Где |
|---|---|
| Тексты сервисов | `model/services/<slug>.ts`, порядок — `model/services/index.ts` |
| Тексты главной | `model/hub.ts` |
| Подписи кнопок и формы | `model/copy.ts` |
| Кадры (скрины, видео) | `model/shots.ts` → задание на съёмку `SHOTS.md` |
| Заявка на демо | `model/demo-request.ts` (проверка, ловушка) → `app/api/platform-lead` → общие ворота форм сайта `app/api/_site-inbox` (повтор, лимит на посетителя, ключ сайта) → бэк bot `POST /api/site-lead` (`BOT_API_URL`) → бот поддержки «AprilClient» → Telegram-чат «April Client» |
| Вёрстка | `components/*` — один компонент на файл, данные только из `model` |

## Кадры

Кадр без `src` на проде не рисуется, при разработке на его месте рамка «что снять».
Как добавить снятый кадр — в шапке `SHOTS.md`. `SHOTS.md` собирается из реестра:
после правки `model/shots.ts` запустите тест `__tests__/shots.test.ts` с `UPDATE_SHOTS=1`.

## Новый сервис

1. Адрес — в `PLATFORM_SERVICE_SLUGS` (`model/types.ts`), иконка — в `lib/service-icons.ts`.
2. Тексты — новый файл в `model/services/`, подключить в `model/services/index.ts`.
3. Кадры — в `model/shots.ts`, затем пересобрать `SHOTS.md`.
4. Тесты раздела: `pnpm exec vitest run "app/(landing)/platform/__tests__"`.
