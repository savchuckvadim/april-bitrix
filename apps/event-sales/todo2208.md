# Задачи 22.08 — статус

## 1) Отказы: сделка не закрывалась ✅ (баг бэка)

Причина: калькулятор стадий при **нерезультативном** отчёте с отказом просил стадию
`sales_noresult`, а в воронке «ОП Основная» такой стадии **не существует** (лестница:
new → cold → warm → pres → offer_create → document_send → refine → in_progress →
money_await → supply → success → fail → double). Код не резолвился, сервис писал в лог
«target stage not resolved» и **вообще не двигал сделку**.

Теперь отказ закрывает сделку всегда (`sales_fail`), независимо от результативности —
«не очень» + отказ это обычный финал недозвонной цепочки. У воронки ХО стадия
`cold_noresult` реально есть, там развилка сохранена. Тест-фикстура содержала
несуществующую стадию — поправлена, чтобы впредь ловить такое.

## 2) «Нет презентационных сделок» при продаже ✅

Причина: список приходил с бэкового `event-support/deals`, а это **заглушка**
(`EventSupportStubService` отдаёт `allPresentationDeals: null`) — значит пусто было
всегда, независимо от количества презентаций.

Теперь фронт берёт презентации сам, прямо из портала: воронка презентаций из слепка,
клиент — компания встройки, **закрытые НЕ отсекаются** (продажу присоединяют именно к
состоявшейся презентации). Запрос ленивый — только когда выбран статус «Продажа».
Пустой список теперь честно говорит «презентаций у клиента нет», а во время загрузки —
«ищем презентации…».

## 4) Зачем история из карточки компании — объяснение (правок нет)

Основной источник истории — **портальный список «ОП История»** (`sales_history`),
который читается напрямую с фронта по CRM-привязкам: компания, сделки, лиды, контакты
текущего контекста (`CO_431`, `D_5512`, `L_318051`, `C_917`), по 50 записей на привязку.
Бэкового эндпоинта нет — `event-support/history` тоже заглушка.

Из **полей самой компании** (`op_history`, `op_mhistory`) история берётся только как
запасной вариант — когда списка «ОП История» на портале нет вовсе. В этом случае над
блоком стоит подпись «из полей клиента», чтобы было видно: это не полноценная лента.

Показывается в двух местах: вкладка «История» в карточке дела и секция на экране
клиента. Грузится лениво — при появлении секции, не на старте приложения.

## 5) Миниатюра контакта рядом с заявкой ✅

Когда рядом стоит заявка (места вдвое меньше), миниатюра контакта показывает **телефон
и почту** вместо полоски характеристик — то, чем пользуются в разговоре. Один контакт
без заявки — как было, с характеристиками.

## 6) Порядок кнопок ✅

«Обновить» переехала **после «создать»**, перед служебными (возврат к фрейму, темы):
это редкое действие-починка, ему не место первым в строке.

## 7) Баг «Что-то пошло не так» при выборе контакта в плане ✅

Две независимые причины:

1. **Экран ошибки на пустом месте.** Глобальный обработчик показывал «Что-то пошло не
   так» на ЛЮБОЕ событие `window.error` — включая браузерное предупреждение
   «ResizeObserver loop completed with undelivered notifications». Это не ошибка
   приложения: браузер сообщает, что наблюдатель размеров не уложился в кадр (его
   поднимают стеклянные поверхности и выпадающие списки, когда меряют себя при
   открытии). Приходит оно **без объекта ошибки** — отсюда и «Global error caught: null»
   в консоли. Теперь такое сообщение игнорируется, остальные ошибки ловятся как прежде.
2. **RadioGroup uncontrolled → controlled.** Список типов события стартовал с
   `value: undefined`, и Radix считал его неуправляемым; как только тип проставлялся
   (предвыбор, перенос) — ругался в консоль. Теперь значение задано всегда.

## 8) Ширина селекта статуса компании ✅

Была по содержимому — при каждой смене статуса чип менял размер и сдвигал всю правую
часть шапки. Теперь ширина фиксированная, длинное название обрезается (полное видно в
раскрытом списке).
