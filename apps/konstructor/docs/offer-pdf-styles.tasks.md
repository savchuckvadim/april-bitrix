# Стили PDF-КП: первая волна, палитры, логотипы, запоминание

15.11.2026. План работ по новым стилям КП в PDF. Как устроены стили и как добавить новый — в бэке,
`back/apps/konstructor/src/offer-pdf/STYLES.md`. Здесь — что решил владелец и что осталось сделать.

## 1. Решения владельца

1. По умолчанию — «Классический». Менеджер меняет стиль сам.
2. Стили могут быть любых цветов: бренд Гаранта (синий, белый, красный) и дерзкие (розовый, оранжевый).
3. Элементы Canva использовать можно: КП делаются только при продаже ГАРАНТа.
4. Года на титульниках нет. Титульник строится по образцу вордовских шаблонов: комплект и поставка
   крупно, клиент с ИНН, кто подготовил.
5. Тёмные обложки (наборы 4, 15, 16, 21) — только титульник, внутренние листы светлые.
6. Кубы (набор 4) пока не берём: сначала то, что проще и чище.
7. Наборы, которые отличаются только цветом, объединяются в один стиль с выбором гаммы (палитры).
8. «Искра» — отдельный стиль с текстом про сервис. В выборе виден всегда, менеджер решает сам.
9. Текст «Вот уже 35 лет…» — портальный (порталы вставляют туда название комплекта). Пока как есть и
   только в «Модерне»; позже — портальный динамический текст. В остальных стилях тексты зашиты в код.
10. Логотипы Гаранта и Искры — вектором, в цвет палитры.
11. Подложка «Призмы» остаётся в поле. Стилям с фоном во всю страницу нужны таблицы и блоки на
    «подложке-карточке»: отступы, скругление, белый фон (у тёмной темы — тёмный фон и светлые линии).
12. Названия — концептуальные, одним словом (раздел 2). «Монохром» и «Графит» могут стать разными
    стилями.
13. Работаем в деве: код `modern` можно переименовать, сделки его ещё не запомнили.

## 3. Каркас (kit) — что добавить

1. **Палитры.** У стиля список гамм `{ code, name, swatch }`; гамма переопределяет цвета темы и, у
   растровых стилей, картинки фона. В запросе — поле `palette`, в списке стилей — гаммы, превью стиля
   принимает гамму. Без гаммы — первая.
2. **Логотипы.** Гарант и Искра из `back/storage/app/logos/*.svg` — модулем с путями (одна заливка),
   компонент рисует их в цвет темы, на тёмном — белым. Проверено мини-рендером 15.11.
3. **Фоны-картинки.** Каталог `offer-pdf/assets` (правило assets в nest-cli, как у шрифтов). PNG
   из материалов ужимаются в JPEG; титульник — фон во всю страницу, внутренние листы — свой фон.
4. **Карточки.** В теме — поверхность `surface { background, radius, padding }`. Если она задана,
   письмо и разделы (наполнение, цена, подпись) ложатся на карточки и читаются поверх любого фона.
   Проверить разрыв карточки между страницами (фон и скругление у кусков) аудитом раскладки.
5. **Промо-страница.** Страница с текстом после титульника: у «Искры» — про сервис, у «Модерна» —
   юбилейный текст, у остальных — общий текст про ИПО ГАРАНТ (пишем своими словами, владелец правит).
6. **Наполнение в две колонки** — как в вордовском «Модерне».

## 4. Запоминание выбора

Уровни: менеджер (последний выбор для новых сделок), сделка, вариант, избранное. Что сохраняется:
формат (Word/PDF), стиль, гамма, титульник, настройки.

### Как сейчас (разбор 15.11)

- Настройки PDF — один набор в localStorage браузера (`offerPdfDocumentPrefs`): не привязаны ни к
  сделке, ни к менеджеру; письмо и номер документа из одной сделки переезжают в другую.
- Сделка, вариант и избранное — строки одной таблицы `bx_document_deals` (поле `kind`: deal, variant,
  favorite, promotion) с одинаковым слепком SnapshotV2 в JSON-колонке `rows`. Бэк `rows` не разбирает.
  Из документа в слепке сейчас только `templateId` (Word-шаблон).
- Слепок пишется на «Сформировать КП», отправке в сделку, договоре, отчёте о поставке, закупках;
  вариант — при создании и после каждого сохранения сделки, пока он открыт; избранное — при создании,
  дальше не меняется. Поток PDF слепок не сохраняет.
- Личные умолчания менеджера уже живут в `app_cache` (app + домен + пользователь + ключ): так хранится
  поставщик по умолчанию (`document-provider`).
- Word-шаблон выбирается так: из слепка сделки → текущий у пользователя → умолчание портала → первый.

### Предложение

1. **Сделка, вариант, избранное** — поле `pdf` в SnapshotV2: `{ format, templateCode, palette,
   withCover, settings }`. Одна правка фронта (`serialize`/`restore`) покрывает все три уровня и пишется
   в уже существующих точках сохранения. Добавить сохранение слепка при генерации PDF.
2. **Менеджер** — ключ `offer-pdf` в `app_cache` рядом с `document-provider`: последний выбор,
   пишется при смене. localStorage остаётся быстрым кэшем.
3. **Порядок выбора** — как у Word: слепок (сделка, вариант, избранное) → последний выбор менеджера →
   «Классический».
4. **Несколько вариантов в одном КП** (сравнение) печатаются одним документом — стиль берётся со
   сделки.
5. **Номер документа** — в слепок сделки (решено 15.11).
6. **Письмо.** Сейчас портальное письмо лежит в легаси-шаблонах: таблица `templates` (шаблон `offer`
   портала) → поля `letter` (текст в `description`, разметка `<red>`, `<color>`) и `isLetter`.
   У april-garant — шаблон #1, письмо 967 символов, «Вот уже 35 лет…». Base template целиком фронту
   не нужен (выпилен 24.10), поэтому письма переносятся в свою таблицу `offer_letters`:
   - поля: `portal_id`, `bx_user_id` (пусто — письмо портала, задан — личное письмо менеджера),
     `name`, `text` (та же разметка: PDF её уже понимает), `is_default`, `is_active`, `sort`;
   - перенос: по одному письму портала из `fields.description` шаблона `offer` (легаси продолжает
     читать свои поля, правки дальше — только в новой админке);
   - ✔ 15.11: миграция `online/database/migrations/2026_11_15_120000_create_offer_letters_table.php`,
     модель `OfferLetter` (схема руками), репозиторий `libs/portal-lib/konstructor/src/offer-letter`,
     временная ручка `POST /api/admin/maintenance/offer-letters/import-legacy` (по умолчанию сухой
     запуск, повтор безопасен), кнопка в админке: Конструктор → «Письма КП» (`/konstructor/offer-letter`,
     «Проверить» и «Перенести письма»). Владелец: migrate ✔ → выкладка админ-бэка и админки →
     «Проверить» → «Перенести» → ручку и кнопку убрать, на этом месте — редактирование писем;
   - правка менеджера сохраняется в сделку (слепок), кнопкой — как его личное письмо по умолчанию;
   - порядок: сделка → письмо менеджера → письмо портала → пусто;
   - тексты стилей (промо «Искры» и т. п.) пока зашиты в код.
7. Попутно: шаблон из избранного не применяется, если Word-шаблоны уже загружены (init выходит рано,
   на восстановление слепка никто не реагирует). Тот же путь починить и для PDF.
