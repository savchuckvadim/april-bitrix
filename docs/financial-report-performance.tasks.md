## 1. Симптом

При смене года (или диапазона лет) во вкладке «Финансы» интерфейс жёстко зависает:
виснет вкладка и весь браузер, иногда приходится перезагружать браузер/компьютер.
Чем шире выбранный диапазон лет — тем хуже.

## 2. Диагноз (зафиксирован 2026-07-28)

Цепочка рендера:
`app/report/financial/page.tsx`
→ `modules/widgetes/FinancialReport/FinancialReportWidget.tsx`
→ `modules/feature/deals-report-calculation/TimeLineTable/DealsReportTimelineCompact.tsx`
→ `modules/feature/deals-report-calculation/TimeLineTable/features/TimelineTable.tsx`

Данные: бэкенд отдаёт **весь отчёт одним payload** (все компании × все сделки × все годы)
в Redux (`entities/deals-report`), смена года — чисто клиентский пересчёт + ре-рендер.

Корневые причины (по убыванию вклада):

1. **Нет виртуализации.** `TimelineTable` рендерит ВСЕ компании сразу; контейнер
   `max-h-[700px] overflow-y-auto` лишь скроллит уже построенный DOM.
2. **Огромная стоимость строки.** На каждую компанию:
   - 12 ячеек месяцев × div-полоса **на каждый год диапазона** (`TimelineCell`);
     при диапазоне 2015–2026 это 144 полосы на строку + колонка кросс-годовой индексации;
   - **4 Radix `Tooltip` + 4 `TooltipProvider`** в `components/CompanyStats.tsx` —
     при сотнях компаний тысячи тултип-инстансов;
   - `formatCurrency` создаёт **новый `Intl.NumberFormat` на каждый вызов** (3 на строку).
3. **Синхронный полный ре-рендер.** При смене года все объекты строк новые → React
   пересоздаёт всё дерево одним коммитом, затем браузер пересчитывает layout
   HTML-таблицы (auto table layout по всем ячейкам). Сотни тысяч DOM-узлов × table
   layout = зависание вкладки.
4. **Дублирование тяжёлых расчётов.** `calculateMonthlyPayments` вызывается для каждой
   сделки дважды (`calculateYearlyMatrix` + `calculateCompanyStats`), а при активном
   фильтре «Индексация» `calculateCompanyStats` считается **трижды** на компанию
   (ещё раз в `filteredCompanies` в `DealsReportTimelineCompact.tsx`).
5. **Пикер лет без ограничений.** `YearRangePicker` позволяет выбрать произвольно
   широкий диапазон → стоимость растёт как `строки × 12 × кол-во лет`.
6. **Аномальные данные.** Сделка с датой окончания «2099» генерит тысячи объектов
   платежей (`calculateMonthlyPayments` итерирует по duration без cap).

Почему в `kpi-sales` всё нормально: там отчёт агрегирован на бэке (десятки строк
по менеджерам), нет схемы «строка на компанию × 12 месяцев × годы» по сырым сделкам.
Но длинные списки там есть → общая виртуализация пригодится и ему (см. этап 2).

## 4. Критерии приёмки

- Смена года при любом разумном диапазоне (1–5 лет) — без зависания вкладки;
  коммит рендера < ~200 мс на реальных данных, UI отзывчив (transition).
- DOM таблицы ограничен видимыми строками (~20–30 × стоимость строки), а не всеми
  компаниями.
- Excel-экспорт и итоги/аналитика считаются по полному отфильтрованному набору,
  как раньше.
- Виртуализация оформлена как переиспользуемый компонент `packages/ui`,
  задокументировано его применение (kpi-service — использует; kpi-sales — использует
  или зафиксировано «не требуется»).
